# 06_recall_ui.md

## Recall UI Component Specification

### Overview
The Recall UI allows users to withdraw their own messages before or after posting. It implements secure authorization using recall tokens stored in sessionStorage.

### Security Model
- **Recall Token**: Generated by backend on message creation, returned ONLY once
- **Storage**: sessionStorage only (cleared on tab close)
- **Transmission**: HTTPS only, in request body
- **Validation**: Backend verifies token hash matches stored hash
- **Authorization**: Token required, not just message ID

### User Flow

#### 1. Message Creation
```
User sends message
    ↓
Backend returns { message_id, public_code, recall_token, status }
    ↓
Frontend stores recall_token in sessionStorage[message_id]
    ↓
Message displayed with RecallButton (if recallable)
```

#### 2. Recall Initiation
```
User clicks "THU HỘI" on own message
    ↓
RecallButton checks canRecall(message)
    ↓
If allowed → Show confirmation modal
    ↓
User enters reason (optional) → Clicks "Xác nhận thu hồi"
    ↓
Frontend retrieves token from sessionStorage
    ↓
Calls POST /messages/{id}/recall with token + reason
    ↓
Backend validates token, updates status to RECALLED
    ↓
Realtime/Polling receives update
    ↓
Frontend updates message status
    ↓
sessionStorage[message_id] cleared
    ↓
RecallButton hidden permanently
```

### Recall Eligibility
```typescript
function canRecall(message: Message): boolean {
  const recallableStates: MessageStatus[] = [
    'pending',
    'processing', 
    'awaiting_review',
    'posted',  // Creates reversal transaction
  ];
  
  const hasToken = !!sessionStorage.getItem(`recall_token_${message.id}`);
  const isRecalling = pendingRecalls.has(message.id);
  
  return recallableStates.includes(message.status) && hasToken && !isRecalling;
}
```

### Recall Types

#### Before Posting (pending/processing/awaiting_review)
- Simple status change to RECALLED
- No financial reversal needed
- Message hidden from chat (or shown as recalled)

#### After Posting (posted)
- Creates reversal transaction (bút toán đảo)
- Original transaction marked REVERTED
- Ledger balance adjusted
- Response includes `reversal_transaction_id`

### Error Handling

| HTTP Status | Error Message | User Action |
|-------------|---------------|-------------|
| 403 | "Không có quyền thu hồi: mã không hợp lệ hoặc đã hết hạn" | Cannot recall, token invalid |
| 409 | "Tin nhắn đã được thu hồi hoặc mã đã được sử dụng" | Already recalled |
| 404 | "Không tìm thấy tin nhắn" | Message deleted |
| 500 | "Lỗi máy chủ khi tạo bút toán đảo" | Retry or contact support |

### Token Storage Implementation
```typescript
const RECALL_TOKEN_KEY = 'classfund_recall_tokens';

function storeRecallToken(messageId: string, token: string) {
  const data = JSON.parse(sessionStorage.getItem(RECALL_TOKEN_KEY) || '{}');
  data[messageId] = token;
  sessionStorage.setItem(RECALL_TOKEN_KEY, JSON.stringify(data));
}

function getRecallToken(messageId: string): string | null {
  const data = JSON.parse(sessionStorage.getItem(RECALL_TOKEN_KEY) || '{}');
  return data[messageId] || null;
}

function removeRecallToken(messageId: string) {
  const data = JSON.parse(sessionStorage.getItem(RECALL_TOKEN_KEY) || '{}');
  delete data[messageId];
  sessionStorage.setItem(RECALL_TOKEN_KEY, JSON.stringify(data));
}
```

### Display Rules
- **Only show for own messages** (message.sender_id === currentUser.id)
- **Only show if canRecall returns true**
- **Hide after successful recall**
- **Show "Đã thu hồi" status badge** instead of button
- **Error message** displayed if recall fails

### Accessibility
- Button: aria-label="Thu hồi yêu cầu" / "Yêu cầu đảo bút toán"
- Modal: role="dialog", aria-modal="true"
- Modal: aria-labelledby, aria-describedby
- Reason input: aria-label="Lý do thu hồi"
- Focus trapped in modal
- Escape closes modal

### Testing Scenarios
1. Guest sends message → token stored in sessionStorage
2. Guest clicks "THU HỘI" → modal opens with correct description
3. Guest confirms → recall API called with token
4. Backend returns success → status updated to "Đã thu hồi"
5. Button hidden, status badge shown
6. Guest tries to recall again → button not shown
7. Invalid token → error message displayed
8. Already recalled → error message displayed
9. Posted message recall → reversal transaction created
10. Tab closed → token lost → cannot recall after reopen
