# 14_PHASE_2_ENTRY_CRITERIA.md

## Objective Requirements (Phase 2 Must Satisfy Before Approval)
Every criterion is evidence-based; references Phase 0 / Phase 1 artifacts; references actual source inspection (`ledger.py`, `ollama list`, `git log`); does not assume design = implementation.

### Critical Prerequisites (Must Be VERIFIED, Not Just Designed)
1. **Adapter source files implemented**: `src/lib/supabase/client.ts`, `messages.ts`, `auth.ts`, `storage.ts`; `ai/ollama_client.py`; `worker/main.py`, `claim.py`, `heartbeat.py`. Evidence required: file creation in repository; `git ls-files` confirms; adapter connects to deployed Supabase; adapter uploads/download executes; `ChatView` consumes adapter data (not mock).
2. **Idempotency stability resolved**: Stable idempotency format selected (see `08_FINANCIAL_IDEMPOTENCY_AUDIT.md`: Option A — `message.id` in fingerprint + stable key; or Option B — DB constraint reliance with `message.transaction_id` pre-check). Evidence required: `post_transaction()` modified (if Option A) or worker checks `message.transaction_id` before retry (if Option B); `IdempotencyKey` database behavior verified (same key returns same response; different key with same fingerprint raises `409`); retry loop stable (message either receives `transaction_id` or fails with `failed` after max retries, not infinite retry loop).
3. **Recall authorization mechanism implemented**: Token generation and authorization endpoint implemented; `public_code` excluded from authorization (verified by code inspection: authorization endpoint does not accept `public_code` as authorization parameter); token hash (`recall_token_hash`) created at message insert; authorization endpoint validates hash before allowing recall. Evidence: source code in `app/api/routes/` or adapter; authorization endpoint executes; token creation verified; authorization endpoint rejects missing/invalid token.
4. **Recall before post source implemented**: `message.status` check before `verify_and_post_from_ai()` (either `verify_and_post_from_ai()` accepts `message.id` and checks status, or adapter/work-flow checks before calling). Evidence: source code inspection (`ledger.py` or adapter); `message.status = 'recalled'` aborts posting; `message.status = 'pending'`/`processing'` allows posting; `message.status = 'recalled'` does not call `post_transaction()`.
5. **AI vision accuracy verified**: `qwen2.5vl:3b` vision accuracy measured (>85% at 0.90 confidence threshold) with 20+ Vietnamese bank receipts; timeout verified (<30s average, <60s max); structured JSON output verified (>95% valid JSON). Evidence: `test_vision_accuracy.md` or equivalent; test results recorded; accuracy measurement evidence; `ollama_client.py` vision call executed with real receipt image.
6. **Financial gatekeeper authoritative preserved**: `verify_and_post_from_ai()` remains the only posting path; adapter does not call `post_transaction()` directly; `message.transaction_id` set by `verify_and_post_from_ai()` result; no second balance calculation; `calculate_balance()` preserved. Evidence: `git diff` confirms `ledger.py` unchanged; adapter contracts (`10`, `11`) enforce single path.
7. **Supabase connection verified**: `supabase` connection from adapter (`client.ts`) executed; `messages` insert executed (test fixture or real message); `user_roles` read executed; `RLS` policies executed (`anon` reads verified, `authenticated` insert verified, `authenticated` admin read verified); `realtime` subscription receives at least one event (`INSERT` or `UPDATE`). Evidence: adapter execution log; `git` shows adapter source; `pytest` or manual execution result; `supabase` connection string verified (not hardcoded secrets).
8. **Worker claim/recovery executed**: `UPDATE ... FOR UPDATE SKIP LOCKED` executed against `messages`; claim sets `processing`; heartbeat updates `worker_status`; stale lease (`lease_expires_at < now()`) reset executed; worker startup/reclaim verified (`reclaim_stale_leases()` executes). Evidence: `python worker/main.py` execution log (not continuous server, but claim/recovery tested); `git` shows `main.py`, `claim.py`, `heartbeat.py`; `messages` table shows `processing` claim with `claimed_at` and `worker_id` set.
9. **Ollama adapter executed**: `ai/ollama_client.py` source exists; vision call to `qwen2.5vl:3b` executed; structured JSON output validated; timeout/retry handled; model unavailable detection handled. Evidence: source file; execution result (`test_vision_accuracy.md` or adapter test); `ollama_client.py` connects to `http://127.0.0.1:11434` (localhost); no external tunnel.
10. **End-to-end integration verified**: Guest sends message (`ChatView` or adapter); message persisted (`messages.id` assigned, `public_code` assigned, `status='pending'`); worker claims (`status='processing'`); AI validates (structured output); `verify_and_post_from_ai()` posts (or `awaiting_admin`); `message.transaction_id` set (`posted`); realtime updates frontend (`ChatView` shows `posted`/`awaiting_admin`); recall executed (token authorization); `post_revert()` creates `REVERT`; message `status='recalled'`; original transaction preserved; `audit_logs` records `MESSAGE_PROCESSED`, `RECALL_REQUESTED`, `TRANSACTION_REVERSED`. Evidence: `pytest` end-to-end test (`tests/test_integration.py`) or manual execution log; all steps verified; no failures in flow.

### Security Prerequisites (Must Be Verified)
11. **Service-role isolation verified**: `SERVICE_ROLE_KEY` only in worker/backend environment; `ANON_KEY` only in adapter (`client.ts`); adapter source inspected (`client.ts`); no `SERVICE_ROLE_KEY` reference in `src/lib/supabase/` files.
12. **RLS policies executed**: All table policies (`05` contracts) executed against Supabase; `anon` read verified; `authenticated` insert verified; `authenticated` admin read verified; `authenticated` member read verified; `service_role` bypass verified (worker can claim/update `messages` / `worker_status`); no unauthorized access succeeds.
13. **Public code authorization excluded**: Authorization endpoint (`revert` or equivalent) does not accept `public_code` as authorization parameter; `public_code` used only for display/identification (verified by source inspection).
14. **Ollama localhost-only verified**: `OLLAMA_BASE_URL` remains `http://127.0.0.1:11434`; adapter does not use tunnel or external endpoint; `ollama_client.py` connects to localhost only (verified by adapter source inspection; `netstat` or `lsof` shows `ollama` on `127.0.0.1:11434`; no external binding).

### Integration / Team Boundaries (Must Be Frozen)

Evidence: `git` shows contracts unchanged since Phase 1 (`git diff` between Phase 1 commit and Phase 2 start — contracts preserved); adapter contracts (`06`) reference same contracts.
16. **Module modification restrictions preserved**: No concurrent modifications to `ledger.py` (`11` / `08` audit); no concurrent AI service rewrites (`21` reference); adapter contracts (`06`) frozen; `ChatView` (`15` Phase 0) preserved (adapter only replaces data source).

## Verdict Criteria (Phase 2 Must Not Be Authorized Unless All Critical Prerequisites Verified)

If `16` or `17` not complete: Phase 2 prerequisites incomplete.
If `08_FINANCIAL_IDEMPOTENCY_AUDIT.md` conflict (`idempotency stability`) remains `BLOCKED`: Phase 2 entry blocked (financial reliability risk).
